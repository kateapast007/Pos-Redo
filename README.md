# ПОС — преподавательская оценка студентов

Консольное приложение на C# / .NET 10: преподаватель оценивает студентов по критериям рубрикатора, модель не даёт нарушить правила предметной области, итог считается автоматически по весам. Использованы DDD, архитектура Ports & Adapters и паттерны GoF.

## Возможности
- Добавление студентов и критериев (название, максимальный балл, вес), просмотр списков.
- Выставление, просмотр, исправление и отмена оценок.
- Расчёт итога по одному студенту и по всем.
- Экспорт итогов в CSV и JSON.
- Демонстрация сквозного сценария на отдельном контейнере и отдельном хранилище перед рабочим меню.

## Структура
- `Pos.Domain` — сущности, объекты-значения, инварианты, доменный сервис, порты-репозитории.
- `Pos.Application` — сценарии (`*UseCases`), фасад `PosFacade`, DTO, порт `IReportExporter`.
- `Pos.Infrastructure` — адаптеры: хранилища в памяти, экспорт CSV/JSON.
- `Pos.App` — консольное меню (`ConsoleUI`), демонстрация (`DemoRunner`), DI (`CompositionRoot`).
- `Pos.Tests` — unit-тесты xUnit.

## Архитектура: Ports & Adapters
```
Pos.App  ──►  Pos.Application  ──►  Pos.Domain
  │                  ▲                   ▲
  └──► Pos.Infrastructure ───────────────┘
```
Стрелка означает «зависит от». Все зависимости направлены внутрь, к домену, и закреплены ссылками между проектами: `Pos.Domain` ни на что не ссылается, `Pos.Application` не видит `Pos.Infrastructure`. Порты (`IStudentRepository`, `IRubricRepository`, `IEvaluationRepository`, `IReportExporter`) объявлены во внутренних слоях, их реализации лежат снаружи. DI-контейнер (`Microsoft.Extensions.DependencyInjection`) собирает граф в одном месте — `CompositionRoot.Build()`.

## Язык предметной области и карта DDD
| Слово | Класс | Роль |
|---|---|---|
| студент | `Student` | Entity, идентичность `StudentId` |
| рубрикатор | `Rubric` | корень агрегата, внутри него `Criterion` |
| критерий | `Criterion` | Entity внутри `Rubric`, создаётся только рубрикатором |
| оценка | `Evaluation` | Entity, идентичность `EvaluationKey` = студент + критерий |
| балл, вес, итог | `Score`, `Weight`, `FinalGrade` | Value Object: неизменяемые, равны по значению, сами проверяют себя |

Разница между Entity и Value Object: два студента с одинаковым именем — два разных `Student` (разные `Id`), а два `Score` со значением 7 — одно и то же значение.

Границы агрегатов: `Rubric` (вместе с критериями), `Student` и `Evaluation` — три отдельных агрегата, друг на друга они ссылаются только по идентификаторам.

| Инвариант | Кто охраняет |
|---|---|
| балл не отрицательный | `Score` |
| балл не больше максимума критерия | `Criterion.EnsureAccepts` (вызывается из фабрики и из `Evaluation.Correct`) |
| оценка только по критерию из рубрикатора | `Rubric.GetCriterion` (используется фабрикой) |
| вес и максимум больше нуля, названия не пустые | `Weight`, `Criterion`, `Student` |
| одна оценка на пару «студент + критерий» | `EvaluationKey` и сценарий `Grade` |
| итог согласован с оценками и рубрикатором | доменный сервис `FinalGradeCalculator` |

Repository (порты) лежат в домене, реализации `InMemory...Repository` — в инфраструктуре.

Domain Service — `FinalGradeCalculator`: правило «итог согласован с набором оценок» не принадлежит ни студенту, ни оценке, ни рубрикатору по отдельности. Итог по 10-балльной шкале равен сумме (балл / максимум × вес), делённой на сумму весов и умноженной на 10; критерий без оценки считается нулём.

## Паттерны GoF
| Группа | Паттерн | Где | Какую боль закрывает |
|---|---|---|---|
| порождающий | Factory | `EvaluationFactory` | единая точка создания оценки; конструктор `Evaluation` закрыт (`internal`), поэтому нельзя создать оценку в обход проверки критерия и диапазона |
| структурный | Facade | `PosFacade` | один вход во все сценарии: консоль не склеивает сценарии из нескольких сервисов сама |
| поведенческий | Template Method | `ReportExporterBase` → `CsvReportExporter`, `JsonReportExporter` | общий каркас выгрузки (проверка пути, сортировка, отрисовка, запись файла); подкласс определяет только `Render` |

## SOLID
**SRP:** `Rubric` охраняет критерии, `Evaluation` — оценку, `FinalGradeCalculator` — согласованность итога, `ConsoleUI` отвечает только за ввод и вывод.

**DIP:** сценарии зависят от портов, а не от конкретных хранилищ; в тестах `IReportExporter` подменяется заглушкой `ExporterStub`.

**OCP (с оговоркой):** новый формат экспорта добавляется новым наследником `ReportExporterBase` без правки существующего кода, но `ConsoleUI` выбирает пункты меню через `switch`.

## Запуск
Из каталога решения:
```bash
dotnet restore
dotnet build
dotnet test
dotnet run --project src/Pos.App
```
Сначала выполнится демонстрация (отдельное хранилище, файлы итогов появятся в `exports/`), затем откроется рабочее меню с пустыми данными.

Для покрытия:
```bash
dotnet test --collect:"XPlat Code Coverage"
```

## Ограничения
Данные хранятся в памяти и исчезают после завершения приложения. Рубрикатор один на всё приложение.
